### Assignment: Vibe Coding Challenge

### Build, Publish, and Explain an AI-Assisted Application

### Overview

Modern software development is increasingly being shaped by AI-assisted development tools. In this assignment, you will experiment with **vibe coding**, an approach where you focus on describing what you want to build, rapidly testing ideas, and iteratively working with AI coding assistants to turn those ideas into a functioning application.

Your challenge is simple:

**Build something interesting. Make it work. Publish it. Be prepared to explain what you built and how AI helped you build it.**

You may build an application on **any topic you choose** and use **any programming language, framework, AI model, library, API, or AI coding tool**.

The emphasis is on experimentation, creativity, iteration, and learning.



### Learning Outcomes

By completing this assignment, you will demonstrate your ability to:

1. Use generative AI tools to assist with software development.
2. Translate an idea into a functional software application.
3. Use prompting and iterative refinement to improve software.
4. Test and troubleshoot AI-generated code.
5. Use Git and GitHub to manage and publish a software project.
6. Document a software project so that someone else can understand and run it.
7. Critically reflect on the strengths and limitations of AI-assisted development.

### The Challenge

Create a functional application using **vibe coding**.

You are free to decide:

- what the application does
- what problem it solves
- who it is designed for
- which programming language you use
- which development framework you use
- which AI tools you use
- whether the application itself contains AI

Your application does **not** have to be an AI application.

The goal is to use AI as part of the **development process**.



### What Is Vibe Coding?

For this assignment, vibe coding means using natural-language conversations with AI tools to help design, generate, modify, debug, and improve software.

Instead of manually writing every line of code, you might tell an AI coding assistant:

"Create a web application that lets students upload study notes and automatically generates a quiz."

You might then continue:

"Make the interface more modern."

"Add a difficulty selector."

"The quiz score isn't calculating correctly. Find and fix the problem."

"Add a dark mode."

"Refactor the application so the quiz questions are stored separately from the UI."

The development process becomes an iterative conversation:

**Idea → Prompt → Generate → Run → Test → Debug → Improve → Repeat**

### Application Requirements

Your application must demonstrate more than simply generating a single piece of code with AI.

At minimum, the application must include:

### 1. A Clear Purpose

The application should have an identifiable purpose or goal.

Your README should answer:

- What does the application do?
- Who might use it?
- Why did you choose to build it?

### 2. Functional Interaction

The application must allow a user to interact with it.

For example:

- buttons
- forms
- menus
- user input
- game controls
- search
- visualization controls
- file uploads
- chatbot interaction
- API interaction

A static page containing only text does not satisfy this requirement.



### 3. Meaningful Functionality

The application must perform at least one meaningful operation based on user interaction.

Examples:

- analyzing input
- transforming data
- generating recommendations
- running a simulation
- playing a game
- displaying or filtering information
- calling an API
- generating content
- performing calculations
- interacting with an AI model

### 4. Iterative Development

You must demonstrate that the application evolved during development.

For example:

**Version 1**

Basic working application.

**Version 2**

Improved interface.

**Version 3**

Added a new feature.

**Version 4**

Fixed problems discovered during testing.

Your GitHub commit history should provide evidence of this evolution.

### AI Usage

There is intentionally **no limit on the amount of AI assistance you may use**.

AI may help you:

- brainstorm the idea
- choose technologies
- design the interface
- generate code
- generate sample data
- debug errors
- explain unfamiliar code
- refactor code
- create tests
- create documentation
- improve accessibility
- write your README
- generate graphics or assets

However:

**You remain responsible for the final application.**

"The AI generated it" is not an acceptable explanation for why something does or does not work.

You should understand your application well enough to explain its major components.



### GitHub Requirement

Your completed project must be published to a **GitHub repository**.

The repository should contain the complete source code required to run the project.

Your repository should include:

- application source code
- supporting files
- dependency information
- README.md
- .gitignore where appropriate

Do **not** publish passwords, API keys, access tokens, private credentials, or other secrets.

If your application requires an API key, use an environment variable and provide an example such as:

API_KEY=your_api_key_here

Do not commit the real key.



### README Requirements

Your GitHub repository must contain a useful README.md.

Include the following sections:

### Project Name

Name your application.

### Description

Explain what the application does.

### Purpose

Explain why you chose to build it.

### Features

List the major features.

### Technologies

Identify the major languages, frameworks, libraries, APIs, models, and tools used.

### AI Tools Used

Identify the AI development tools you used.

For example:

- GitHub Copilot
- Microsoft Copilot
- ChatGPT
- Claude
- Cursor

### Installation

Explain how someone can install the project.

### Running the Application

Provide clear instructions for starting the application.

For example:

pip install -r requirements.txt

python app.py

or:

npm install

npm run dev

### How AI Was Used

Briefly explain how AI contributed to development.

Include **3 examples of prompts** that significantly influenced the application.

### Screenshots

Include at least **2 screenshots** showing the application working.

### Future Improvements

Describe at least **3 improvements** you would make if development continued.



### Testing Requirement

Before submitting, test your repository as though you were another developer discovering it for the first time.

Confirm that:

- the repository can be cloned
- dependencies can be installed
- the application starts
- the major features work
- instructions match the actual application
- no secrets are included
- there are no obvious broken links or missing files

Ideally, perform this test from a clean directory or environment.



### Reflection

Add a section called **Vibe Coding Reflection** to your README.

Answer the following questions.

### 1. What did AI do particularly well?

Identify an example where AI significantly accelerated development.

### 2. What did AI do poorly?

Describe at least one situation where AI generated incorrect, incomplete, inefficient, or misleading code.

### 3. How did you verify AI-generated code?

Explain how you tested whether the generated solution actually worked.

### 4. How did your prompts evolve?

Give an example of an early prompt and explain how you improved it.

### 5. What did you learn?

Describe something about programming, AI, software development, or prompt engineering that you understand better after completing the project.

### 6. Would you trust AI to build the entire application without human supervision?

Explain why or why not.

### Important Grading Principle

Students are **not graded on how many lines of code they personally write**.

Extensive use of AI is permitted and encouraged. Students are graded on their ability to:

**Imagine → Prompt → Generate → Run → Test → Debug → Evaluate → Improve → Publish → Explain**

A sophisticated application created from a single prompt will not automatically receive a high grade. The submission must demonstrate meaningful testing, iteration, understanding, documentation, and reflection.

### What I Am NOT Grading

You are **not** being graded on how many lines of code you personally typed.

Using AI extensively is expected.

You are also not being graded on whether you used the "best" programming language or framework.

The important question is:

**Can you use AI effectively to turn an idea into working software while understanding, testing, documenting, and taking responsibility for the result?**

### Suggested Development Process

### Step 1: Brainstorm

Ask an AI assistant to generate application ideas based on your interests.

### Step 2: Define an MVP

Identify the smallest version of the application that would demonstrate the core idea.

### Step 3: Choose Your Technology

Ask AI to recommend an appropriate technology stack and explain why.

### Step 4: Generate the Initial Application

Use AI to help create the initial structure.

### Step 5: Run It

Do this early.

Do not wait until the application is "finished."

### Step 6: Find Problems

Test features and deliberately try to break the application.

### Step 7: Vibe Code

Describe problems and improvements to your AI assistant.

For example:

"When I submit the form without entering a name, the application crashes. Fix the problem and add appropriate validation."

### Step 8: Add Features

Gradually expand the project.

### Step 9: Commit Regularly

Use Git throughout the project rather than uploading everything in one final commit.

A healthy development history might look like:

Initial working prototype

Add user input validation

Add visualization

Improve responsive interface

Fix scoring bug

Add dark mode

Update README and screenshots

### Step 10: Test the Final Repository

Clone or download the repository and verify that your own installation instructions work.

### Step 11: Reflect

Consider where AI accelerated your work and where human reasoning remained necessary.



### Important Rule: You Own the Code

AI can generate code extremely quickly.

That does not mean the code is correct.

AI-generated software can contain:

- bugs
- security vulnerabilities
- incorrect assumptions
- nonexistent APIs
- unnecessary dependencies
- poor architecture
- privacy problems
- accessibility problems
- fabricated information

You are responsible for identifying and correcting these problems.

If asked during a demonstration:

**"What does this part of your application do?"**

you should be able to explain it.



### The Vibe Coding Mindset

For this assignment, do not worry about knowing how to build the entire application before you start.

Start with an idea.

Describe it.

Generate something.

Run it.

Break it.

Fix it.

Improve it.

Repeat.

Your goal is not to prove that AI can write code for you.

Your goal is to demonstrate that **you can effectively direct, evaluate, test, and improve AI-generated software to turn an idea into a working application.**
